# 最近抓取手工补充飞书看板设计

**日期:** 2026-08-15  
**状态:** 已批准  
**语言:** Go + 现有 Web 仪表盘  

## 背景

多账号看板抓取会在「最近抓取」留下成功/失败记录。部分账号失败后，用户希望**手工填入指标**并写入飞书多维表格对应日期，而不是重新自动抓取。

## 目标

1. 「最近抓取」中失败/跳过记录醒目标记；任意历史行的账号可点击打开手工补充表单。
2. 用户选择游戏、填写飞书同名指标（允许部分留空），提交后写入看板表。
3. 飞书「日期」= 该历史条目所在分组的日历日（YYYY-MM-DD），表单只读不可改。
4. 账号、店铺名、UID 从本地账户库带出（有则写入）。
5. 若已存在「日期 + 账号 + 游戏」行：**整行覆盖**（未填指标对应字段清空）。
6. 若不存在：新增一行；视图按日期排序时与同日其他行聚合展示。

## 非目标

- 任何补抓 / 重跑抓取 / 自动登录。
- 用户在表单中修改日期。
- Excel 式物理插行、下移行（飞书多维表不支持；依赖日期字段排序）。
- 修改正常自动抓取的飞书同步策略（仍按接口统计日 upsert；手工路径独立）。

## UI

### 最近抓取列表

- 失败类（`skipped` / 非 `ok`）：沿用错误/警告 badge，行增加轻微高亮（如左边框或背景）。
- 「账号」列：可点击（链接或按钮样式），打开补充弹窗。
- 弹窗打开时带入：`date`（分组日）、`account`（手机号）。

### 补充弹窗

| 控件 | 行为 |
|------|------|
| 日期 | 只读，来自历史分组日 |
| 账号 | 只读 |
| 游戏 | 下拉，选项 = 配置/代码中的看板游戏列表（与抓取一致） |
| 指标输入 | 咨询量、发起报价量、回收成功订单数、回收成功金额、回收成功率、回收满意度、回收主页咨询量、回收主页成功订单数；均可空 |
| 提交 / 取消 | 提交调 API；成功关闭并 toast；失败展示错误 |

校验：日期、账号、游戏必填；指标若填写须为数字（允许小数，成功率可不带 `%`）。

## API

### `POST /api/board/manual`

请求 JSON：

```json
{
  "date": "2026-08-14",
  "account": "13800000001",
  "game": "原神",
  "metrics": {
    "咨询量": 10,
    "发起报价量": null,
    "回收成功订单数": 1
  }
}
```

- `metrics` 的 key 为飞书列名；缺省或 `null` 表示该字段置空。
- 服务端解析账户：按用户名匹配账户库，填充店铺名、UID（Cookie 中 `ieu_member_uid`，若可读）。
- 「抓取时间」写提交时刻本地格式文本；「错误信息」手工补充时写空（覆盖时清空）。

响应：

```json
{ "status": "ok", "action": "created" | "updated" }
```

错误：`400` 校验失败；`404` 账号不存在；`503` 飞书未配置；飞书 API 失败返回 `502` + 信息。

### 可选历史追加

提交成功后向 scrape history 追加一条：`status=manual`（或 `ok`），`error` 可为空或简述「手工补充 {game}」，便于追溯。实现时优先 `manual` 以便 UI 区分。

## 飞书写入

复用 `feishu.BitableOps`：

1. `EnsureBoardFields`（与自动同步相同列）。
2. `listAllRecords` 建 `日期|账号|游戏` → record_id 索引。
3. 组装**完整**字段 map（日期、账号、店铺名、UID、游戏、各指标、抓取时间、错误信息）。
   - 未提交的指标：**显式写入空**（更新时清空原值；新建则表现为空单元格）。
4. 命中则 `PUT` 整行；否则 `batch_create` / 单条创建。

与自动同步差异：手工路径对空指标是「清空」，自动路径通常是「有值才写、不主动清未抓到的列」（保持现有行为不变）。

## 游戏列表来源

与抓取配置一致：优先 `config.scraper` / 现有 `gameNameToID` 的游戏名集合；Web 可提供 `GET /api/board/games` 或在 `/api/status` 附带，供下拉使用。

## 测试

- 手工写入：新建行、覆盖行（空字段清空）、非法数字、缺游戏、账号不存在。
- UI/API：失败行可点；提交成功返回 `created`/`updated`。
- 回归：自动 `SyncBoardStats` 仍不删除旧行。

## 实现顺序

1. `feishu`：`UpsertBoardManualRow`（或等价）支持整行覆盖含清空。
2. Web：`POST /api/board/manual` + 游戏列表。
3. `index.html`：历史高亮、弹窗、提交。
4. 测试 + 重建 `gui.exe` / `scraper.exe`。
